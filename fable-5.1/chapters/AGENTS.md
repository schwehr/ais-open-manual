# `chapters/`

This directory holds the body of **The AIS Handbook**, an open, citable handbook
on the maritime Automatic Identification System. It contains all 69 chapters,
organised into ten parts (Part I through Part X), each as a pair of files:
`chNN-slug.md` (the chapter text, GitHub-flavored Markdown with LaTeX math,
ASCII/Mermaid diagrams, and runnable code snippets) and `chNN-slug.bibtex`
(every work cited in that chapter, in BibTeX form).

The chapters reference sibling top-level directories by relative path:
figures live in `../figures/chNN/`, table-driven appendices in
`../appendices/`, and longer runnable scripts in `../code/` (e.g.
`code/tdma/sotdma_sim.py`, `code/rf/linkbudget.py`,
`code/security/kinematic_checks.py`, `code/analytics/duckdb_density.py`).
The per-chapter `.bibtex` files are the inputs to the repository-wide
`../BIBLIOGRAPHY.bib`. The governing template for every file here is
`../STYLE_GUIDE.md`; `../TABLE_OF_CONTENTS.md` and `../SUMMARY.md` list the
chapters in order.

## Files

Each row is one chapter: `chNN-slug.md` plus its companion `chNN-slug.bibtex`.
The `.bibtex` note gives the entry count and the character of the sources.

## Notes for agents

- **One chapter = two files.** Every `chNN-slug.md` has a matching
  `chNN-slug.bibtex`. When you add or change a citation in a chapter, update
  both the chapter's `## References` list and its `.bibtex` file (and keep
  `../BIBLIOGRAPHY.bib` consistent; `../CONTRIBUTING.md` describes the
  intended rebuild step). Never rename one file without the other.
- **Fixed chapter template** (`../STYLE_GUIDE.md` §2). Each `.md` starts with
  `# Chapter N — Title`, then a `> **Part X — Part title.**` blockquote, then a
  bold `**In this chapter.**` abstract, then numbered sections `## N.1 …`
  (subsections `### N.1.1`). All 69 chapters then end with the same top-level
  headings in this order: `## Then & now`, optional `## On the wire` (present
  in 37 chapters; required for 13, 20–28, 30, 34, 39, 44, 59–61, 68, 69),
  `## Validation, uncertainty & data quality`, `## Software`,
  `## Standards & guides`, `## Pitfalls`, `## Key takeaways`, `## References`.
  Keep this order; the style guide describes a checker that enforces it.
- **Parts** are declared by the blockquote, not by directory structure:
  I = ch01–08, II = ch09–12, III = ch13–19, IV = ch20–26, V = ch27–36,
  VI = ch37–43, VII = ch44–50, VIII = ch51–57, IX = ch58–65, X = ch66–69.
- **Recurring boxes** are blockquotes with a bold label (`> **Case file.**`,
  `> **On the wire.**`, `> **Try it.**`, `> **Worked example.**`,
  `> **Definitions that bite.**`, `> **Threat model.**`, `> **Legal note.**`,
  `> **Rule of thumb.**`). Threat model and Legal note boxes are required in
  the security/transmission chapters (33, 42, 58–65, 67).
- **Cross-references** are relative Markdown links: other chapters as
  `[Chapter 21](ch21-link-layer-tdma.md)` (hundreds of such links exist, so
  renaming a slug breaks many files), appendices as
  `../appendices/appendix-X-slug.md`, figures as `../figures/chNN/name.svg`
  with alt text. Tables are Markdown, never images.
- **Code** longer than ~25 lines lives in `../code/` and is referenced from
  the chapter; the most-referenced scripts are `code/tdma/sotdma_sim.py`,
  `code/rf/linkbudget.py`, `code/security/kinematic_checks.py`,
  `code/analytics/duckdb_density.py`, `code/viz/blender_ais_animation.py`,
  `code/rf/propagation_compare.py`, and `code/decode/tagblock.py`. Inline
  snippets mostly use `pyais`, pandas, and DuckDB; the repository's
  `../pytest.ini` and `../requirements.txt` govern running them (`pytest -q code`).
- **Citation style:** author–year in text, e.g. "(Balduzzi, Pasta & Wilhoit
  2014)" or "(ITU-R M.1371-6, Annex 2 §3.3.4)" — there are no `[@key]` or
  `\cite{}` tokens in the Markdown. BibTeX keys follow `AuthorYEARkeyword`
  (e.g. `Balduzzi2014ais`) or issuer-and-id for standards (e.g.
  `ITU_M1371_6`, `IMO_MSC74_69`). Entry types in use include `@techreport`,
  `@standard`, `@article`, `@misc`, `@inproceedings`, `@patent`, `@manual`,
  `@report`, `@book`, and a few `@software`/`@online`/`@legislation`/
  `@regulation`. Every `.bibtex` has at least 10 entries (13–27 observed).
- **Honesty rules** (`../CONTRIBUTING.md`, `../STYLE_GUIDE.md`): never invent
  citations, DOIs, court cases, patents, CVE ids, statistics, or model
  numbers; mark unconfirmed facts "(verify)"; cite accident findings only to
  the official investigation report; security content is detection- and
  defence-oriented — no transmit instructions or exploit code.
- **Units and terminology:** SI first, nmi/kn where mariners use them,
  frequencies in MHz, power in W/dBm, gain in dBi, tonnage as GT; bold and
  define terms on first use in each chapter. Fast-moving facts carry
  "as of <Month YYYY>". Files are UTF-8 with LF line endings and very long
  (paragraph-per-line) lines.
- The style guide and CONTRIBUTING reference `tools/check_book.py`,
  `tools/check_xrefs.py`, `tools/build_bibliography.py`, and `manifest.json`;
  neither `tools/` nor `manifest.json` is present in this checkout, so the
  template above is the practical specification to follow.
